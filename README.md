# Baranchik Sound

Музика та автоматичне оповіщення про тривогу.

Вебзастосунок для закладу: показує стан повітряної тривоги, відтворює сигнали, вручну вибрану персоналом локальну музику та привітання «Гамарджос».

**Це допоміжний інструмент. Він не замінює офіційні сирени, сповіщення, вказівки ДСНС або органів влади.** Заклад має самостійно контролювати офіційні канали оповіщення.

## Вимоги

- Node.js 18+ та npm 9+ для збірки.
- Vercel або Netlify для хостингу; на Vercel токен обслуговує вбудована serverless function `/api/alerts`, альтернативно можна розгорнути Cloudflare Worker.
- Для роботи потрібні стабільний інтернет, доступні файли сигналів і перший дотик до екрана після кожного перезавантаження сторінки, щоб розблокувати звук.
- Цільова сумісність: iPhone 6 / iOS 12 / Safari 12 та сучасні телефони. Перевіряйте iOS 12 лише на production-збірці через `npm run preview:lan`.

## Токен

Отримайте особистий API-токен на [devs.alerts.in.ua](https://devs.alerts.in.ua/): увійдіть або створіть обліковий запис і створіть токен у кабінеті розробника. Назви розділів сайту можуть змінюватися.

Відкрийте «Налаштування» сайту, введіть токен і натисніть «Зберегти». Він зберігається лише в `localStorage` цього пристрою; повторно вводити його після перезавантаження сторінки не потрібно. Також можна використати одноразове посилання з фрагментом `#t=...`: сайт збереже токен і відразу прибере фрагмент з адресного рядка.

У вихідному коді та `dist` токена немає. Для Vercel задайте `ALERTS_TOKEN` у Project Settings → Environment Variables: вбудована function `/api/alerts` прочитає його на сервері та передасть API як Bearer. Не використовуйте префікс `VITE_`, не додавайте токен у `venue.json`, GitHub або URL. Для іншого хостингу можна використати Cloudflare Worker із `proxyUrl` у `venue.json`. Клієнт обмежує всі API-виклики (опитування, перевірка та самотест) до 8 запитів за рухомі 60 секунд. Усі пристрої однієї Wi-Fi мережі ділять IP і спільний ліміт API.

Щоб замінити токен, введіть нове значення в налаштуваннях і збережіть його. Посилання з `#t=` містить секрет до першого відкриття: після використання видаліть його з історії повідомлень і браузера.

## Запуск у закладі

Для локального запуску в закладі використовуйте вбудований Node proxy-сервер без сторонніх залежностей. Він роздає `dist/` з кешом для статичних файлів і проксі-рутом `/api/alerts` до `https://api.alerts.in.ua` через `Authorization: Bearer`.

```bash
npm install
npm run build
cp .env.example .env.local
# потім відредагуйте .env.local і задайте ALERTS_TOKEN=
npm start
```

Після запуску відкрийте адресу з консолі на iPhone, наприклад `http://192.168.1.42:4174`. Для локального доступу з телефону потрібна одна Wi‑Fi мережа та відкритий порт 4174 у брандмауері/маршрутизаторі. Якщо iPhone не бачить сервер, перевірте, що ПК і телефон в одному Wi‑Fi, брандмауер не блокує порт, і що на PC не вимкнено локальні мережеві сервіси.

Локальний proxy працює за замовчуванням: в [public/venue.json](public/venue.json) є `"proxyUrl": "api/alerts"`. У браузері токен не запитують, не показують і не надсилають до API напряму. Якщо сервер недоступний або `/api/alerts` повертає 404, застосунок показує повідомлення: «Проксі недоступний. Запустіть npm start. Потім можна ввести токен як запасний варіант.» Тільки після цього дозволяється ручний ввід токена як резервний варіант. Якщо `ALERTS_TOKEN` не задано на сервері, /api/alerts повертає 503 і повідомлення «На сервері не задано ALERTS_TOKEN».

Для автозапуску на macOS можна використовувати LaunchAgent або Script в `~/Library/LaunchAgents`, а на Windows — Task Scheduler. У короткому варіанті достатньо запускати `npm start` у окремому терміналі і залишити його відкритим на ПК. Для публічної інфраструктури або інтернет-розгортання залишковий Cloudflare Worker є необов’язковою опцією, але не замінює локальний закладський proxy.

### Під час помилок API

- `401`: токен відсутній або скасувався/прострочений.
- `403`: IP або країна не має доступу до API.
- `429`: ліміт запитів; чекайте `Retry-After` або 60 секунд.
- `503`: дефіцит `ALERTS_TOKEN` на сервері.
- `502`: помилка мережі/проксі до upstream.
- `504`: timeout до API.

## Як перевірити сайт

1. Виконайте `npm run build`.
2. Опублікуйте папку `dist` (наприклад, через Netlify Drop).
3. Відкрийте сайт на iPhone.
4. У налаштуваннях виберіть область, район і громаду/місто; якщо довідник недоступний, повторіть завантаження або введіть UID вручну. Без вибраної локації API не опитується.
5. Для direct API введіть токен або відкрийте одноразове посилання з `#t=`; у proxy-режимі токен у браузері не потрібен.
6. Торкніться екрана, щоб розблокувати звук.
7. Відкрийте «Діагностика» → «Самотест».

Для responsive-перевірки встановіть WebKit і запустіть `npm run test:e2e`. Тест збирає production bundle та зберігає основний екран і відкрите меню для розмірів 320×568, 360×640, 375×667, 414×896, 768×1024 і 667×375 у `design/screenshots/`.

## Деплой на Vercel

1. Імпортуйте GitHub-репозиторій у Vercel. Налаштування в `vercel.json` задають `npm run build` і каталог `dist`.
2. У Vercel відкрийте **Project → Settings → Environment Variables** і створіть `ALERTS_TOKEN` для Production (і Preview, якщо потрібне тестове середовище). Значення вводьте лише у Vercel Dashboard; не додавайте його до GitHub Secrets для звичайного deploy.
3. Збережіть змінну та запустіть новий deployment: зміни Environment Variables застосовуються лише до нових deployment.
4. Переконайтеся, що у `public/venue.json` залишено `"proxyUrl": "api/alerts"`. Це same-origin шлях до Vercel Function; URL зовнішнього proxy не потрібен.
5. Відкрийте `https://<ваш-домен>/api/alerts`: успішна відповідь має бути JSON з полем `alerts`. Тіло помилки не містить токен.

Функція обмежує запити за IP і кешує успішну відповідь на 5 секунд. Для додаткових production-доменів безпечніше використовувати той самий origin сайту або окремо налаштувати дозволені origins у proxy.

## Файли та медіа

```text
public/

	manifest.webmanifest

	images/hero.jpeg       # фонове зображення закладу (необов’язкове)

	gamarjos.json          # генерується автоматично
	gamarjos/              # файли привітання
	sounds/
		Tryvoga-Kremenchuk-Yellow.mp3
		Tryvoga-Kremenchuk-Red.mp3
		Tryvoga-Vidbii_01.mp3
	fonts/                 # локальні WOFF2
```

Файли сигналів задаються в `venue.json`: `yellow`, `red`, `clear`. Стандартні імена — `Tryvoga-Kremenchuk-Yellow.mp3`, `Tryvoga-Kremenchuk-Red.mp3`, `Tryvoga-Vidbii_01.mp3`. Можна вказати інші шляхи, але самі імена файлів у коді не зашиті. Рівень гучності визначається аудіофайлом; застосунок не може програмно змінити системну гучність iPhone.

### Музика

Працівник вручну вибирає один локальний MP3, M4A, AAC, WAV, FLAC або OGG у меню «Музика»; новий вибір зупиняє і замінює попередній файл. На головному екрані доступні «Грати / Пауза» та «На поточний час»: позиція рахується від `music.syncStart` і зациклюється за тривалістю треку. Час початку відліку можна змінити в меню, значення зберігається локально.

Файл вибирається в меню й не завантажується на сервер або в localStorage; після reload його потрібно вибрати знову. Для Safari/iOS застосунок пробує вихідний `File` (A), typed slice (B), а для файлів до 150 MiB — повну копію через FileReader (C). На iOS 12 для локального файла до 32 MiB Data URL готується після вибору, щоб `play()` лишався синхронним у наступному жесті користувача (D). На iPhone 6 рекомендуємо компактний MP3 та достатній обсяг вільної пам'яті. Файл має бути збережений локально на iPhone, а не лише в iCloud: завантажте його в «Файли на iPhone» перед вибором.

У меню «Музика» кнопка «Перевірити файл» читає перші й останні 64 KiB з timeout 15 с і запускає muted playback check для тих самих стратегій. Діагностика показує результат кожної спроби, MIME, результат `canPlayType()`, тип і розмір файлу, час до metadata, media error, ready/network state, preload і результат `play()`. Повідомлення про недоступний файл означає, що iOS не може прочитати його локально. `NotSupportedError` і media error 4 означають, що Safari відхилив source/формат або кодек; самі по собі вони не доводять нестачу пам'яті. Для файлів понад 150 MiB пропускається лише резервне повне читання C, тому на старому iPhone краще використати локальний MP3 до 150 MiB. Якщо всі стратегії не спрацювали, перекодуйте файл у звичайний MP3 128 кбіт/с або перевірте, що це аудіофайл, а не потік чи плейлист. Поза одноразовим ланцюгом автоматичних повторів немає.

Object URL попереднього треку звільняється лише після призначення й завантаження нового source; усі URL звільняються при закритті сторінки. `#music` має `preload="metadata"`, без `crossorigin` і `autoplay`. Перший виклик `play()` виконується безпосередньо в обробнику «Грати» через Safari user gesture. Silent audio unlock використовує короткий PCM WAV 44.1 кГц/16-bit у Blob URL; перед синхронним `play()` кожен audio викликає `load()`. CSP дозволяє `media-src 'self' blob: data:`; Data URL використовується тільки для обмеженої iOS 12 копії музики, не для unlock. Під час сигналу або «Гамарджос» музика ставиться на паузу й повертається з тієї самої позиції лише якщо персонал не натискав «Пауза».

### Гамарджос

Покладіть аудіофайли у `public/gamarjos/`. Випадковий файл не повторюється двічі поспіль, якщо в папці є більше одного. Повторне натискання під час привітання запускає той самий файл з початку; під час тривоги привітання стає в чергу. Порожня папка — штатний стан: кнопка недоступна з підписом «Додайте файл у public/gamarjos».

### `venue.json`

Конфігурація читається під час запуску й перевіряється; помилкова структура показується як помилка завантаження конфігурації.

| Поле                       | Призначення                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `venueName`                | Назва закладу в шапці та заголовку сторінки.                                                                                                |
| `tagline`                  | Необов’язковий короткий підзаголовок закладу під назвою.                                                                                    |
| `theme.heroImage`          | Необов’язковий відносний шлях до фонового JPEG; порожнє або недоступне зображення лишає світлу підкладку.                                   |
| `logo`                     | Відносний шлях або URL логотипу; порожній рядок вмикає текстові ініціали.                                                                   |
| `pollIntervalSec`          | Інтервал опитування; default 12 секунд, мінімум 10. Мережеві повтори використовують backoff 24/48/60 секунд.                                |
| `staleAfterSec`            | Вік `meta.last_updated_at`, після якого показується stale без зміни стану; без `meta` stale настає після 3 хвилин без успішної відповіді.   |
| `alerts.auth`              | `query` (default) або `bearer` для direct API. Worker сам додає Bearer upstream.                                                            |
| `alerts.locationUid`       | Не використовується як default. Місце вибирається вручну і зберігається під ключем `locationUid` у `localStorage` пристрою.                 |
| `alerts.clearConfirmPolls` | Кількість послідовних успішних відповідей `none`, потрібна для сигналу відбою.                                                              |
| `music.syncStart`          | Початок щоденного відліку для «На поточний час», формат `HH:MM`; змінене значення зберігається у `localStorage`.                            |
| `music.dayRolloverHour`    | Година, до якої час до `syncStart` належить попередньому дню; стандартно `5`.                                                               |
| `signals.yellow`           | Шлях до сигналу жовтого рівня.                                                                                                              |
| `signals.red`              | Шлях до сигналу червоного рівня.                                                                                                            |
| `signals.clear`            | Шлях до сигналу відбою.                                                                                                                     |
| `signals.activeHours`      | `null` — сигнали доступні весь час; інакше `{ "start": "HH:MM", "end": "HH:MM" }`. Поза інтервалом сигнал не грає, але стан UI оновлюється. |
| `gamarjos.dir`             | Каталог привітань; стандартна структура використовує `gamarjos`.                                                                            |
| `proxyUrl`                 | Повний URL Worker `/alerts`; порожній рядок означає прямий API-запит із токеном у локальних налаштуваннях браузера.                         |

Селектори локацій показують область → район → громаду/місто й сортуються українською. Зіставлення тривоги робиться тільки за UID: вибрана локація, її район і область; для міст зі спеціальним статусом враховується лише власний UID. Швидкий пошук громади обмежений обраною областю. Текстових фільтрів у UI немає.

Генератор сканує лише `public/gamarjos`. Музичний плейлист формується з вибраних працівником файлів у браузері.

### Фон

Фонове зображення задається через `theme.heroImage`. Рекомендований JPEG — шириною близько 1080 px і розміром до 300 КБ; якість експорту 70–80%. Якщо файл не задано або він недоступний, застосунок використовує світлий фон.

## Довідник локацій

`public/locations.json` оновлюється зі списку UID alerts.in.ua під час `npm run dev` і `npm run build`. Для ручного оновлення виконайте `npm run make-locations`.

Якщо Google Sheets недоступний, відкрийте [таблицю локацій](https://docs.google.com/spreadsheets/d/1XnTOzcPHd1LZUrarR1Fk43FUyl8Ae6a6M7pcwDRjNdA/edit?usp=sharing), виберіть **Файл → Завантажити → CSV**, створіть `data/locations.csv` та покладіть завантажений CSV туди. Наступний запуск генератора використає цей файл. Якщо мережа й CSV недоступні, але `public/locations.json` уже існує, поточний довідник буде збережено.

## Cloudflare Worker

Worker зберігає `ALERTS_TOKEN` як Cloudflare secret, дозволяє лише точний `ALLOWED_ORIGIN`, кешує успішний API-відгук на 5 секунд і не повертає токен у тілі відповіді чи логах.

1. У `worker/wrangler.toml` замініть `ALLOWED_ORIGIN` на origin сайту, наприклад `https://menu.example.com` — без шляху та кінцевого `/`.
2. Створіть secret: `npx wrangler secret put ALERTS_TOKEN --config worker/wrangler.toml`.
3. Розгорніть Worker: `npm run worker:deploy`.
4. Запишіть Worker endpoint у `public/venue.json`, наприклад `"proxyUrl": "https://restaurant-alerts-proxy.<account>.workers.dev/alerts"`, і перебудуйте сайт.
5. Перевірте доступ із дозволеного origin:

```sh
curl -i -H 'Origin: https://menu.example.com' \
	'https://restaurant-alerts-proxy.<account>.workers.dev/alerts'
```

Запит з іншого origin має отримати `403` без `Access-Control-Allow-Origin`. API-токен не додається до конфігурації сайту або GitHub secrets для deploy сайту.

## Розробка та деплой

```sh
npm ci
npm run dev
npm test
npm run lint
npx tsc --noEmit
npm run worker:typecheck
npm run build
npm run preview:lan
```

GitHub Actions запускає lint, тести, typecheck і production build на pull request та push до `main`. Push до `main` деплоїть `dist` у Netlify. Додайте repository secrets `NETLIFY_AUTH_TOKEN` і `NETLIFY_SITE_ID`; вони використовуються лише deploy job. API-токен для цього не потрібен.

`public/_headers` задає `no-cache` для HTML і конфігурацій, `immutable` для hashed assets і `max-age=86400` для сигналів та привітань. CSP генерується під час build у `dist/index.html` і `dist/_headers`. Стилі є зовнішнім asset, щоб працював `style-src 'self'`.

## Новий заклад

1. Збережіть каталоги `public/gamarjos` і `public/sounds`.
2. Замініть назву у `public/venue.json`, задайте файли сигналів і за потреби proxy URL. Місце не задається конфігурацією: персонал обирає його в меню на кожному пристрої.
3. Покладіть сигнали та привітання в відповідні каталоги. Персонал вибиратиме музику на телефоні після відкриття сторінки.
4. Виконайте `npm run build`, перевірте результат через `npm run preview:lan` і перевірте CORS Worker для нового origin.
5. Деплойте сайт. Код застосунку для зміни закладу змінювати не потрібно.

## Діагностика

- Немає токена: перевірте налаштування токена або `proxyUrl`. Якщо `proxyUrl` заданий, token field прихований.
- «Немає зв'язку»: перевірте Wi-Fi, HTTP/CORS, Worker secret і `ALLOWED_ORIGIN`; після трьох помилок стан тривоги не змінюється. Backoff збільшує інтервал повтору до 60 секунд; `401` зупиняє запити до зміни токена/режиму, `429` враховує `Retry-After` або чекає 60 секунд.
- «Дані застаріли»: перевірте доступність API та час його відповіді; stale сам по собі не змінює стан і не грає сигнал.
- «Перевірка API» показує активні локації у вибраних областях, рівень, чи визнано подію нашою, і причину рішення.
- `?sim=1` дозволяє перевірити стани none/yellow/red, помилку мережі, stale та час без реального API.
- «Копіювати діагностику» містить останні події та runtime-параметри без API-токена.

## Постійна робота на iPhone

- Підключіть телефон до зарядки.
- Вимкніть «Режим енергозбереження».
- У «Автоблокуванні» виберіть «Ніколи».
- Увімкніть «Керований доступ» і за потреби заблокуйте Safari на сторінці застосунку потрійним натисканням кнопки «Додому».
- Увімкніть автоматичні дату, час і часовий пояс.
- Вимкніть автоматичне оновлення iOS і сповіщення. «Не турбувати» залиште вимкненим.
- Переконайтеся, що гучність виставлена фізичними кнопками. Застосунок не може змінювати системну гучність; сигнали можуть бути гучнішими лише через рівень самих аудіофайлів.
- Використовуйте стабільний Wi-Fi. Залишайте Safari відкритим на сторінці.
- Після перезавантаження телефона або сторінки торкніться екрана, щоб розблокувати аудіо, і виберіть локальні музичні файли заново. iOS блокує програмне відтворення звуку без дотику.

На iOS 12 не можна блокувати екран або згортати Safari: система може призупинити виконання сторінки й відтворення. Wake Lock використовується лише там, де браузер його підтримує, і не скасовує це обмеження iOS 12.

## Ліцензування

Право на публічне відтворення музики та аудіопривітань — окрема відповідальність закладу. Переконайтеся, що ліцензії та договори покривають використання в конкретному приміщенні й форматі роботи.
